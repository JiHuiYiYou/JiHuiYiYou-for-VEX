### ② 黄金参考

同一份 JHYY 源码：

- **A 路**（第 0 步）：JHYY → C → clang → ELF → `.bin`
- **B 路**（将来）：JHYY → ARM 机器码 → ELF → `.bin`

两条路的产物**行为一致**，且**逐层可定位**：
`.s` / `.o` / ELF / `.map` / 最终 `.bin` **全部留存**，不只存 `.bin` ⇒
B 阶段对拍时能回答"从哪一层开始不一致"。

> ⚠️ **"一致"指的是行为，不是字节。**
>
> 事实基线 § 2 那条"命令行产物与 GUI 产物逐字节相同"是**同一工具链的两条调用路径**，
> 跟 A/B 不是一回事：A/B 是**两个不同的代码生成器** —— `.s` 必然不同，`.o` 段布局也可能不同。
>
> ⇒ **五层产物是「各自的诊断证据」，不是逐字节比对对象。**
> 对拍要回答的问题是"同一输入下两路的**行为**是否一致"；
> 逐层比对只是为了**定位**不一致发生在哪一层，
> 别把事实基线 § 2 那条（同一工具链两条调用路径）的标准错移过来。

### ③ 实机可跑

A 路产出的 `.bin` **真的在 Brain 上转了电机**（不是"应该能跑"）。

## 2. 拆解

### Day 0 — 先别写 emitter（✅ 已完成）

**做法**：手工写 C，**零 JHYY 变量**，用实测过的工具链纯手工走通
`源码 → ELF → 带签名 bin → program.bin`。
（探针 = `main.c` + 绑定面封装 `jhyy_vex.c`；另有单独的 ABI 测量探针 `day0-abi/`。）

**为什么这样切**：VEX 侧的一切在 emitter 存在之前都是未知数。
不先把它实测掉，B 阶段一旦烧不亮，你分不清是签名放错段、栈没设、`.bss` 没清，
还是寄存器分配器把 r0 弄丢了。

| 实测事实 | [`00-事实基线.md`](00-事实基线.md) 全文 |

**已实测的关键结论**（详见事实基线）：

- 产物格式**不需要额外转换器** —— SDK 的 `objcopy` 路径直出最终格式；
  头 32 字节 `XVX5` + 版本 1，入口 `0x03800020`。
- **启动链完全闭合**：`.boot:vexStartup` → 清 bss/sbss → stdlib 版本校验 →
  newlib impure data → `__libc_init_array` → `vexMain` → `__libc_fini_array`。
- **并发模型**：用户的 `main` 是 `vexTaskAdd(main, 2, "MAIN")` 注册的 **task**。
  ⇒ 顺带一条硬事实：**入口符号必须叫 `main`**（SDK 用 `R_ARM_ABS32 main` 取地址），
  B 路发射的符号必须**不带修饰**。
- **ABI 锁定 softfp**（我们与 `libv5rt.a` 双向一致）。
- **struct 布局实测**：packed / 非 packed 都有；C API 里**只有一个**按值传的 struct，
  ≤4 B ⇒ 寄存器传参（详见事实基线 § 8.1）。
- **JHYY 侧的硬约束**（ABI v4.0.0 § 6 / § 9）：不支持变参、不支持 struct 按值跨 FFI、
  `extern fn` 参数类型**不做编译期检查**（错了是**静默不符**）、
  指针宽度**锁死 64 位** ⇒ ARM 目标得先定成 4 字节，否则连 `extern fn` 都对不上。
- **指令集是 ARM 态 4 字节定长** ⇒ 后端不必做 Thumb-2 变长编码。
- **没有隐藏的全局初始化**（`vexcodeInit` 是工程自带的空壳）。
- 内存预算：堆 1 MB / 栈 14 KB / 代码段 1.6 KB。

### Day 1–2 — emitter 发 **C**，不发 C++

**理由**：绑定层是 `extern "C"`，输出 C 就没有 name mangling，
`extern fn` 一一对应，少一整类问题。

**最小子集**（够用即可，不许扩）：

常量 · `let` · 算术 · `if` / `while` · 函数调用 · `extern fn` 声明 ·
字符串字面量 · struct 布局

**最小绑定面**（不许一上来 400 个 API）：确切清单见事实基线 § 9.2 —— 先只绑

```
vexDeviceGetByIndex / vexDeviceMotorVelocitySet / vexDelay
jhyy_vex_display_puts          ← 屏显走**非变参封装**，不是 vexDisplayPrintf
```

> ⚠️ **不要把 `vexDisplayPrintf` 写进绑定面。**
> 它是**变参**函数，JHYY 不支持变参调用（ABI v4.0.0 § 6 FFI）。
> A 路能"调"只是因为 clang 替它展开了 —— 那是 C 编译器的能力，不是 JHYY 的；
> B 路（直出机器码）**没有**这个能力。
> ⇒ 两路在这个调用点上会**既不是同一个符号、也不是同一份语义** ⇒
> "同一份 JHYY 源码行为一致"被打穿。
>
> 替代品 `jhyy_vex_display_puts` 已在第 0 步探针里做好（事实基线 § 9.4），
> 签名固定、**两路调的是同一个符号**。**其余等真的需要时再加。**

### 3.1 emitter 是**探针**，不是产品

- emitter 代码**不追求**通用、完整、可维护。
- 遇到"这个特性 JHYY 现在不支持" ⇒ **记进规格书的问题清单，不在 emitter 里绕过**。
  （例：`fn(...)` 类型位置不被认 ⇒ 记下来，别自己造个函数指针类型硬塞。）

### 3.2 进入 B 阶段的条件

同时满足才允许动 B：

- [x] 规格书八项全部有实测值 —— **八项全部实测完毕**（tick 频率 = 100 Hz，§ 13.1）
- [x] A 路 `.bin` 已在 Brain 上转过电机 —— **2026-11-09 实机确认**（`Q1=moved`，§ 13.1）
- [x] `.s` / `.o` / ELF / `.map` / `.bin` 五层产物齐全且留存
      —— **留存口径 = 本地留存 + 可复现脚本 + 一份哈希清单**（事实基线 § 2.1），
        **不是"进版本库"**：`.gitignore` 忽略 `build/` 与各类产物是**有意**的，
        因为 `.bin` / ELF 含 `libv5rt.a` 的代码（VEX 专有），

### 3.3 A 路的产物**不是废品**，但也不是遗产

- **是**：B 阶段的黄金参考 —— 同一份源码两条路，行为必须一致。
- **是**：规格书的可执行副本。
- **不是**：未来要长期维护的第二套后端。
  ⇒ emitter 代码在 B 阶段**只保留最小可用状态**（够跑对拍用例即可），
  不得反向长成"JHYY 的 C 后端"。

### 3.4 一条硬边界：**永久旁路，不回灌**

**语言主仓（JiHuiYiYou）只管语言；VEX 这套目标支持由本仓自己养。**

- 本仓对主仓的改动一律是**旁路**：**不改**主仓工作树、**不主动回灌**、**不承诺合入**。
- 本仓的 VEX 专属产物（C emitter 探针、未来的 ARM 后端 overlay 与 `abi_arm_v5.jhyy`）
  **长期住在本仓**，由本仓维护 —— 本仓就是一个**独立的目标支持仓**。
- ⚠️ **门不焊死**：**不主动、不等待、不承诺** ——
  若上游**自行**长出了"从外部目录加载目标"这类**通用机制**，
  本仓可以**被动收编**（零成本挂上去）；合不合是顺手的事，不写死"永不"。

#### 3.4.1 永久旁路的代价（本仓自己接住的三件事）

| # | 义务 | 落地口径 |
|---|---|---|
| 1 | **文档口径** | 本仓的一切措辞按"独立分发物"写 —— **不写**"待 PR / 落回主仓" |
| 2 | **上游同步** | **pin** 到明确的主仓 commit（§ 3.4.2）；每次主仓发版**重叠一次** + 跑一遍本仓最小门 |
| 3 | **本仓自己的门** | 主仓的门（自举 byte-equal / artifact 新鲜度 / 全量回归）**不覆盖**旁路文件 ⇒ 本仓补一套**最小门**（§ 6.4） |

#### 3.4.2 pin 口径

| 项 | 值 |
|---|---|
| 主仓 commit（pin） | **`be6d37b72afe77f88e32500361cdefd979d1653b`**（release v4.1.5） |
| 取用方式 | **影子构建**：`scripts/overlay-build.sh` —— 把主仓源码树复制到本仓的临时目录，再叠加本仓的 overlay 文件 |
| 主仓工作树 | **全程不动**（只读一份 checkout） |
| overlay 真源 | [`../spike/overlay`](../spike/overlay)（本仓的 JHYY 源文件） |

> ⚠️ **pin 的意义**：规格书里的每条实测结论都是"**哪一版编译器**上测出来的"。
> 没有 pin，三年后没人说得清 VEX 的实测对应的是哪版编译器 ——
> 「尺子不知道自己量的是哪版东西」。
>
> ⚠️ **pin 的是源码，不是二进制**：影子构建出的 `jhyy.exe` 会随**本机 gcc 版本**漂移
> （主仓自己的 **W-117 工具链漂移检查**查的就是这个；影子构建不是发布 ⇒ 该检查关掉）。
> ⇒ 实测结论要写清是「**源码 commit X + 本机 gcc Y**」，不能只写 commit。

#### 3.4.3 「指针宽度 8→4」落在共享层 —— **但原型路径绕开了它**

已定位到具体文件（核查主仓 `be6d37b7`）：

| 文件 | 位置 | 现状 |
|---|---|---|
| `compiler/src0/ir.jhyy` | `qbe_type_of()`：`KIND_POINTER` / `KIND_REF` / `KIND_CAP` / `KIND_SLICE` 一律 `QBE_L()`（'l' = 8 字节） | **共享层** |
| `compiler/src0/types.jhyy` | `size_of()`：`KIND_REF` → `8` | **共享层** |
| 主仓 ABI 文档 `jhyy-abi-v4.0.0.md` | 类型表 `*T` 的大小/对齐 = 8/8、锁定项「指针宽度（64 位）」 | **共享文档** |

⇒ **如果**要把 VEX 做成「编译器里的一个后端」，这两处就得改 ⇒ 旁路要**长期 patch 共享文件**
⇒ 上游每动一次就可能冲突，而「不回灌」意味着**没有「合回去一了百了」那天**。

⇒ ★ **但原型不需要**（2026-11-10 实测走通）：
**B 路先在本仓做成 assembler emitter**（[`../spike/route-b`](../spike/route-b)）——
`JHYY → AST → **ARM 汇编** → clang → .bin` ⇒
**寄存器与宽度由 emitter 自己决定**，压根不经过编译器那层共享的
`qbe_type_of()` / `size_of()` ⇒ **原型阶段完全不用 patch 编译器的共享层** ✔

⇒ 所以「要不要给主仓加一个 ARM 后端」这个决定**可以推迟**：
先在旁路把 B 路做通、对拍过，再决定要不要落进编译器（若落 ⇒ 就是 § 3.4.3 的那笔账）。

⇒ 若真要落进编译器，两条路（§ 3.4「门不焊死」的态度）：
- **(A)** pin 死主仓版本、明确宣布不再跟进上游（实验仓口径：诚实、省心）
- **(B)** 把那两处做成**极小且显式**的 patch，并写进同步清单（长期跟上游口径）
- **(C)** 给主仓提一个**纯机制**的 PR：让**目标自己声明指针宽度**
  （对任何新目标都有用的通用能力 ⇒ **不是回灌 VEX 知识** ⇒ 不违反本节契约 ✓）

> 📌 **顺带澄清**（事实基线 § 8.1 那句容易误导）：
> 「指针宽度锁 64 位 ⇒ ARM 目标得先定成 4 字节」**只卡 B 路（直出机器码）**。
> **C 路（Day 1–2）不受影响** —— emitter 发的是 C 类型，宽度由 clang 的 `-target thumbv7` 决定。

## 4. 明确不做

| 不做 | 理由 |
|---|---|
| 一开始绑全部 VEX API | 400+ API 会让 emitter 变成产品（见 § 3.1） |
| 在 emitter 里造 JHYY 没有的语言特性 | 那属于主仓的编译器演进，不是第 0 步 |
| 直接改主仓加 C 后端 | 见 § 3.4；先在本仓实测 |
| 碰赛季代码 | 本项目定位：**纯技术探索**，不动 7262A 的比赛代码 |
| 实现 Thumb-2 变长编码 | 实测：目标是 ARM 态 4 字节定长 |
| 把变参函数写进绑定面 | JHYY 不支持变参调用；变参只允许发生在 C 内部（见事实基线 § 9.4） |
| 在 § 14.2「SDK 再分发」的事实缺口解决前把含 `libv5rt.a` 的产物传进公开 repo | 产物含 VEX 专有代码；本地留存 + 哈希清单已足够对拍 |

### 6.2 本地门（需要 VEXcode Pro V5 ⇒ CI 上跑不了）

| 门 | 命令 | 管什么 |
|---|---|---|
| **产物门** | `scripts/check-artifacts.sh spike/day0-c day0c` | 重建黄金参考，核对**事实基线 § 2.1 里写的哈希 / 大小 / 头部魔数 / 入口地址** |

### 6.3 加新门的规矩

1. 门清单**只加在这一节**，别在 CI 文件里另起一份。
2. **CI 门必须在 stock runner 上真的能跑**；跑不了的 ⇒ 归本地门，并写清楚为什么。
3. 门必须有**能红的证据**：要么带自测，要么在某次真实改动里红过一次。
   恒绿的门不是门，是噪音。

### 6.4 本仓最小门（**旁路专用** —— 主仓的门覆盖不到这些文件）

永久旁路（§ 3.4）的一个直接后果：**主仓的验证门只管主仓那棵树**。
本仓自己的 overlay 文件**没有人管** ⇒ 实测会慢慢失去支撑 ⇒ 本仓自己补最小门：

| 门 | 管什么 |
|---|---|
| **对拍门**（`spike/day1-emit/run.sh` + `corpus-run.sh`） | 同一个 JHYY 源，**emitter 那条路**与**主仓编译器那条路**：stdout **逐字相同** + 返回码相同（`corpus-run.sh` 跑**整个语料**） |
| **overlay 门**（`scripts/overlay-build.sh`） | ① 影子构建在 **pin 的主仓 commit**（§ 3.4.2）上**能编过**<br>② 主仓 HEAD 偏离 pin 时**提醒**（同步义务） |
| **VEX 构建门**（`spike/day1-emit/build-vex.sh`） | 生成物与入库那份**逐字节相同** + 入口符号 `main` 不带修饰 + 绑定面符号在产物里 |
| **绑定面表门**（`spike/binding/binding_surface.py --check-sdk`） | 表里的**精确 C 原型**与 **SDK 头文件逐字一致** ⇒ SDK 升级了、表没跟上 ⇒ 门会红 |
| **Day 3 对照门**（`spike/day3-cmp/build-all.sh`） | 三份产物都编得出 + 绑定面 `.o` 三份逐字节相同 + 入口符号 + ARM 态 + 无 VFP + **A/B 调用集合与顺序相同** |
| **A/B 行为对拍门**（`spike/vex-mock/diff-ab.sh`） | **A 路与 B 路在 PC 上跑出逐行相同的调用轨迹 + 逐字相同的屏显**（本地门：要主仓编译器） |
| **mock 门**（`spike/vex-mock/selftest.sh`） | host mock 的**确定性**（同源两遍轨迹逐字节相同）+ **敏感**（改一个参数轨迹必须变）+ **判读** ⇒ mock 可靠 ⇒ 差分测试成立 |

> 这条门随 overlay 一起实现（Day 1–2 的 C emitter 不需要它 —— C emitter 是独立工具，
> 只吃 `jhyy dump` 的输出，不进编译器 ⇒ 不受主仓门的影响 ✓）。
>
> ⚠️ **没有这条门，"断言必须有实测支撑"就慢慢空掉** —— 旁路文件没人管，
> 出问题时先怀疑的是"是不是编译器变了"。
