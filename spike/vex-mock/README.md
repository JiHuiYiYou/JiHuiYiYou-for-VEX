# vex-mock —— **VEX API 的 host mock**（桌面侧副产物，验收线 § 5）

> **一句话**：在**没有机器人**的情况下，证明「同一段逻辑的两种写法」行为一致。

## 它解决什么

把一个程序从 C++ 翻成 JHYY（或者反过来），最贵的验证是"上机器人跑一遍比一比"。
⇒ 而**上机器人很麻烦**（要插电机、要烧录、要拍照）。

⇒ **本 mock** 让**两个实现**都在 PC 上跑一遍，比**调用轨迹**：

```
原 C++ 程序 ──┐
               ├─→ 同一个 mock（记录每次 API 调用 + 参数 + 读到的值）
JHYY 翻译版 ──┘        ↓
                   两份轨迹 diff ⇒ 相同 ⇒ 语义等价
```

## ★ 为什么 mock 的"植物模型"可以很粗

比的是**两个实现**，不是机器人的真实动力学 ⇒
mock 只要 **① 确定 ② 两边一模一样** 就有意义 ⇒
⇒ 任何"更真实的电机模型"都是浪费。

当前的模型（刻意很粗）：

- 速度一阶趋近命令（时间常数 100 ms），`vexDelay(ms)` 时推进
- 位置 = 速度积分（**°/s = RPM × 6**，事实基线 § 9.7 实测）
- 反转标志**翻转命令方向**（SDK 文档：inverts the motor commands）
- 刹车模式 Brakes/Hold ⇒ 速度命令为 0 时直接停住

## ★ 它**不能**替代真机

**B 路（JHYY → ARM 机器码）的产物是裸机码** ⇒ host 上跑不了（qemu 也不行，没有固件）
⇒ **只有 B 路的行为必须上机验**（见 [`docs/第1步-上机清单.md`](../../docs/%E7%AC%AC1%E6%AD%A5-%E4%B8%8A%E6%9C%BA%E6%B8%85%E5%8D%95.md)）。

mock 替代的是「**同一段逻辑的两种写法**」的等价性验证 ⇒ 那才是**大部分**验证量。

## 它实现的正好是绑定面表

`spike/binding/binding_surface.py`（唯一真相源）里的 **13 个函数**，逐个对应 ⇒
JHYY 程序**一个字都不用改**就能在 host 上跑。

配套的 host 侧头文件：

| 文件 | 是什么 |
|---|---|
| `v5.h` | host 侧的 `v5.h`：**只**声明绑定面用到的 SDK 类型（`V5_DeviceT` / 三个 enum，**值与 SDK 逐字相同**）⇒ 生成的 C 一个字都不用改 |
| `jhyy_vex.h` | host 侧的绑定面声明（原型与 SDK **逐字相同**） |
| `vex_mock.c` / `.h` | mock 实现 + 轨迹/状态 API |
| `runner.c` | host runner（生成的 C 的 `main` 用 `-Dmain=jhyy_main` 改名 ⇒ runner 提供真 `main`） |

## 用法

```bash
bash spike/vex-mock/run-host.sh spike/day3-cmp/cmp.jhyy 3000
```

⇒ stdout = **调用轨迹**（每行 `序号 函数名 参数…`），stderr = 屏上文字。

自测（**证明它能红**）：

```bash
bash spike/vex-mock/selftest.sh
```

- ① **确定性**：同一份源跑两遍 ⇒ 轨迹**逐字节相同**（不成立 ⇒ 差分测试在比噪声）
- ② **敏感**：把速度 50 改成 40 ⇒ 轨迹**必须不同**（不成立 ⇒ mock 没在跑程序 ⇒ 恒绿假信号）
- ③ **判读**：`cmp.jhyy` 的四行结论符合模型（`MOTOR MOVED` / `CONFIG OK` / `REVF FLIP` / `JHY CMP DONE`）

> ⚠️ 这道自测**需要主仓编译器**（`jhyy dump`）⇒ 是**本地门**，不是 CI 门。

## 它已经给出的一个**预测**

`cmp.jhyy` 的第三行 `REVF FLIP` —— mock 预测**反转标志会翻转物理方向**
⇒ 下周那趟上机，机器人应当也显示 `REVF FLIP`。
**不一致 ⇒ 就是真发现**（不是"mock 不准"，而是要查 SDK 的真实行为）。
