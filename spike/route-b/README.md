# route-b —— B 路：JHYY 直出 ARM 机器码（探针）

> **一句话**：把一份 JHYY 源码变成 **ARM 汇编**，编成 V5 的 `.bin`。
> **主仓一行都不用改**（永久旁路，见验收线 § 3.4）。

## 它和 A 路差在哪

| | A 路（[`../day1-emit`](../day1-emit)） | **B 路（本目录）** |
|---|---|---|
| 中间产物 | **C 源码** → clang | **ARM 汇编** → clang |
| 谁定宽度 | clang（`-target thumbv7` ⇒ 指针 4 字节） | **本 emitter 自己定**（寄存器与宽度） |
| 要改编译器吗 | 不用 | **不用**（共享层那两处绕开了，§ 3.4.3） |

⇒ 两条路**烧同一份 JHYY 程序**、**屏幕上看到同样的输出** = 行为对拍 ✔
（产物**不是**同一个字节：2516 B vs 2580 B —— 事实基线 § 2 说得很清楚：
五层产物是**诊断证据**，不是逐字节比对对象。）

## 跑一遍

```bash
bash spike/route-b/build-vex.sh
```

五步：① `jhyy dump`（主仓的命令）② AST → **ARM 汇编** ③ **核对生成物与入库那份逐字节相同**
（防漂移）④ 用 VEX 工程编（`.s` 由 clang 汇编、`.c` 一起链）⑤ **核对符号**：
入口 `main` 不带修饰、绑定面符号在产物里、用户代码是 **ARM 态 4 字节定长**。

## 目标与 ABI

| | |
|---|---|
| 目标 | VEX V5 Brain（ARMv7-A，**ARM 态**，4 字节定长指令） |
| ABI | AAPCS：r0–r3 传参、r0 返回、调用点 sp 8 字节对齐 |
| 浮点 | **不碰** ⇒ 不产生任何 VFP 指令 ⇒ **softfp 天然满足**（§ 7） |
| 入口符号 | `main_jhyy` → **`main`**（VEX 的 `vexMain` 用 `R_ARM_ABS32 main` 取它，§ 9.3） |
| 指针宽度 | **4 字节**（VEX 的 `V5_DeviceT`）⇒ 由 emitter 自己定，不经过编译器的 64 位假设 |

## 代码生成策略：栈机

每个表达式的结果落在 **r0**；二元运算把左操作数压栈、再算右操作数。
简单但正确 —— 探针要的是**对拍一致**，不是快。

已核实（事实基线 § 2.1）：

- 三条路（黄金参考 / A 路 / B 路）的 `jhyy_vex.o` **哈希完全相同** ⇒
  **调的是同一个绑定面符号**，字节层面坐实 ✔
- 入口 `main` 不带修饰 ✔
- 用户代码是 ARM 态（`e92d4ff0` / `e24dd008` / `e59f0058` …）✔
- 产物逐字节可复现 ✔

## 现在支持什么

| 能力 | 状态 |
|---|---|
| i32 / u32 / bool / 4 字节指针 | ✔ |
| `let`（带类型或推导）/ 赋值 | ✔ |
| 算术（`+ - * / %`）/ 比较 / 短路 `&&` `\|\|` | ✔ |
| `if` / `else` / `while` / `return` | ✔ |
| 函数调用（≤ 4 个实参，AAPCS） | ✔ |
| 字符串字面量（`.rodata` + 字面量池） | ✔ |
| extern fn 调用（`bl`，链接期解析） | ✔ |
| i64 / 浮点 | ✘ **报错**（要寄存器对 / VFP ⇒ 记进问题清单） |
| struct / 数组 / 字段 / 索引 | ✘ **报错**（要按布局算偏移） |
| > 4 个实参 | ✘ **报错**（AAPCS 的栈传参还没做） |

> ⚠️ 按验收线 § 3.1：**不支持的就报错，不在 emitter 里绕过**
> （悄悄发出去 = 编译过但行为错，比编不过更糟）。
